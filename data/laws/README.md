# 法律文献存放目录

把要入库的法律文件直接放进这个文件夹，然后运行：

```bash
./.venv/Scripts/python.exe scripts/ingest_folder.py
```

脚本会扫描本目录下所有 `.docx` / `.pdf`，逐份解析成结构化条文，
合并写入 `data/corpus/all.jsonl`，并重建向量索引。

---

## 文件命名

**文件名就是法律全称**，入库后会成为 `law_name` 字段，用于引用展示和法源校验。

```
✅ 中华人民共和国民法典.docx
✅ 中华人民共和国劳动法_20181229.docx          ← 日期后缀会自动剥掉
✅ 中华人民共和国宪法（2018年修正文本）.pdf     ← 版本说明会自动剥掉
❌ 民法典(1).docx
❌ 下载.docx
```

自动剥离的三类噪声：

| 噪声 | 例子 | 入库后 |
|---|---|---|
| 书名号 | `《中华人民共和国民法典》` | 中华人民共和国民法典 |
| 日期后缀 | `中华人民共和国劳动法_20181229` | 中华人民共和国劳动法 |
| 版本说明 | `宪法（2018年修正文本）` | 中华人民共和国宪法 |

同一部法律的 docx 与 pdf 会被识别为重复，只保留 docx。

## 格式要求

### ✅ docx —— 首选

Word 导出的、带文本层的 `.docx` 都可以。

要求文档里**条文以「第X条」单独起段**：

```
第一章　总则

第一条　为了保护民事主体的合法权益……
　　第二条　民法调整平等主体的自然人……
```

- 章的标题写成 `第X章 章名`，脚本会自动记录到 `chapter` 字段
- 条的正文可以有多个自然段（款），会被合并保留
- 目录会被自动跳过
- 序言（第一条之前的内容）会被丢弃

### ✅ 文本版 PDF —— 可用，但**优先用 docx**

Word 导出、官方发布、能选中文字的 PDF 都可以，脚本用 `pypdf` 提取文本层。

**同一部法律同时有 docx 和 pdf 时，脚本会自动选 docx 并跳过 pdf。** 实测原因：

| 文件 | 条数 | 问题 |
|---|---|---|
| 商标法.docx | 87 条 | 无缺号、无重复 |
| 商标法.pdf | 105 条 | 含 18 条假条 |

PDF 提取有两个真实陷阱，脚本已经处理，但仍不如 docx 干净：

1. **条号内混入空格**：「第二十七条」→「第二十七 条」。不处理会静默漏条
   （民用航空法 PDF 因此漏了 16 条）
2. **正文引用折行到行首**：「违反本法第十六条至第十九条……规定的」折行后
   以「第十六条」开头，会被误判成新条文，造出正文只有「至」一个字的假条

处理后的效果（同一份 PDF）：

```
修复前  民用航空法 247 条（缺 16 号）
修复后  民用航空法 262 条（无缺号、无重复）
```

### ❌ 扫描版 PDF —— 不可用

拍照、扫描仪生成的 PDF **没有文本层**，提取出来是空的。

**怎么判断**：用 PDF 阅读器打开，试着用鼠标选中一段文字。
- 能选中 → 可以用
- 选不中（只能整页选中或框选） → 是扫描件，需要先 OCR

这类文件脚本会明确报错并跳过，不会静默产出空语料。

## 入库后的检查

脚本跑完会打印每份文件的解析结果：

```
[+] 中华人民共和国民法典.docx → 1260 条（第1-1260条，无缺号）
[!] 中华人民共和国刑法.pdf → 扫描版，跳过（无文本层）
```

**重点看两件事**：

1. **条数**是否与官方条文数一致（民法典 1260 条、劳动合同法 98 条……）
2. **是否有缺号/重号** —— 有的话说明文档格式不规整，需要手动调整源文件

---

## 为什么要按「条」切

法条的语义单元就是「一条」，一条内部各款互相限定（「前款规定的……」
「但有下列情形之一的除外」）。按固定长度切块会出两种事故：

- 检索到半条 → 模型脑补后半条 → 引用编造
- 「但书」被切到另一个块 → 结论完全反向

所以入库单位必须是完整的「条」。
